# 인과적 Paper 실행 계약

## 상태

`multi-horizon-momentum-development-v2`는 Node 연구기와 Kotlin 백테스트의
거래 단위 실행 패리티만 통과한 `UNVERIFIED` 후보이다. 이 문서의 Paper
경로는 미래참조 없이 전진 결과를 수집하기 위한 실행 어댑터이며, 수익성
검증이나 실거래 승인을 의미하지 않는다. 자동 거래소 주문은 허용하지 않는다.

## 입력과 진입 시점

- 전략의 288/2,016/8,640 lookback은 M5 봉 기준이다.
- `openedAt + 5분 <= 평가 시각`인 완전히 닫힌 봉만 전략 입력에 포함한다.
- 닫힌 신호 봉에서는 `ENTRY_PENDING` 상태만 기록한다.
- 진입은 신호 봉 다음의 연속된 M5 봉 시가에 진입 슬리피지를 적용해 체결한다.
- 다음 봉이 연속되지 않으면 진입하지 않고 `NO_CONTIGUOUS_ENTRY_CANDLE`을 기록한다.
- 첫 부팅은 과거 주문을 소급 생성하지 않고 가장 최근 닫힌 봉부터 시작한다.
- 동일한 닫힌 봉은 영속 상태의 `lastProcessedCandleAt`으로 중복 평가하지 않는다.
- 재시작 시 누락된 봉은 열린 포지션의 종료 여부만 순서대로 복원한다. 중단 중
  발생한 대기 진입은 만료시키고 과거 신규 진입을 소급 체결하지 않는다.

## 공유 실행 정책

Paper와 batch backtest는 다음 공통 컴포넌트를 사용한다.

- `CausalEntryPlanner`: 현재 복리 잔고 기준 위험 금액, 다음 시가 진입,
  구조적/ATR 손절, 최소·최대 위험 거리, UTC 일 진입 제한
- `CausalPositionPolicy`: 동일 봉 손절 우선, 부분 익절, 본전 손절,
  이전 정보로 계산한 ATR trailing, 고정 목표, 최대 보유 봉 종료

현재 후보 기본 계약은 거래당 잔고의 1%, 진입·종료 각각 0.02% 슬리피지,
각 체결 0.06% 수수료, UTC 하루 최대 1건, 고정 목표와 부분 익절 비활성화,
ATR(20) 16배 trailing, 최대 4,032개 M5 봉 보유이다.

## 상태와 복구

상태는 전략·종목·시간 프레임 키로 SQLite에 저장한다.

```text
FLAT -> ENTRY_PENDING -> OPEN -> FLAT
```

- `PAUSE_NEW_ENTRIES` 등 신규 진입 차단 모드에서는 대기 진입을 취소한다.
- 이미 열린 Paper 포지션은 정지 모드에서도 손절·종료 정책을 계속 평가한다.
- 프로세스 재시작 후 대기 진입, 열린 포지션, 잔고, 최고 잔고, MDD,
  손익 합계와 일 진입 횟수를 복원한다.
- 루프는 평가 전에 부족한 공개 M5 이력을 자동으로 채운다. 과거 데이터 페이지가
  Bybit `10006` rate limit을 받으면 최대 5회 지수 backoff 후 fail-closed한다.

## 기록과 API

신호, 주문, 체결, 포지션 스냅샷, 성과 스냅샷과 런타임 상태를 기록한다.
`POST /paper/evaluate` 응답은 기존 필드에 다음을 추가한다.

- `phase`: `FLAT`, `ENTRY_PENDING`, `OPEN`
- `exitReason`: 손절, 목표, trailing, 시간 종료 사유
- `realizedPnl`: 비용과 펀딩을 차감한 종료 손익
- `equity`: 종료 손익을 반영한 복리 잔고

종료 시 Discord에는 종료 사유, 순손익, 변경된 Paper 잔고를 보낸다.

## 검증 근거

- Paper의 증분 실행과 `BacktestRunner` batch 실행을 같은 캔들·전략·비용으로
  재생해 종료 사유, 손익, 최종 잔고가 일치해야 한다.
- 신호 봉 중복 평가, 정지 모드, 다음 봉 체결, 손절 종료, 재시작 상태 복원을
  회귀 테스트로 고정한다.
- 실데이터 Node/Kotlin 패리티는
  [multi-horizon-momentum-execution-parity-v2-2026-08-06.md](multi-horizon-momentum-execution-parity-v2-2026-08-06.md)를 따른다.

## 남은 제한

- 주문·체결·포지션·성과·런타임 상태 쓰기는 아직 하나의 SQLite 트랜잭션으로
  묶이지 않았다. 쓰기 중 프로세스가 종료되면 다음 부팅에서 대사가 필요하다.
- Paper의 OHLC 경로는 봉 내부의 실제 체결 순서를 알 수 없다. TP와 SL이 같은
  봉에서 모두 닿으면 보수적으로 손절을 우선한다.
- 이 단계는 Paper/backtest 정합성만 다룬다. Bybit 실제 부분 체결, 지연,
  주문 거절과 보호 주문 상태 머신의 완전한 공통화는 다음 단계다.
- 현재 후보의 외부·봉인 수익성 게이트는 통과하지 않았다. 따라서 LIVE 자동
  실행 연결, 위험 한도 확대, 수익률 표시는 금지한다.
