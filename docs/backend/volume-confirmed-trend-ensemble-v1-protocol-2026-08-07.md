# 거래량 확인형 멀티 호라이즌 추세 v1 프로토콜

## 판정 경계

이 문서는 `vcte_4h_majority_001` 후보의 계산법과 승인 기준을 외부 거래소 데이터를 읽기 전에 고정한다. Bybit 2020~2026 자료는 후보 발견 과정에서 이미 조회했으므로 전부 개발 자료로 취급한다. 같은 자료에서 좋은 결과가 나와도 실거래 승인 근거로 단독 사용할 수 없다.

Binance USD-M BTCUSDT 자료는 이 프로토콜을 커밋한 다음 처음 취득한다. 결과를 본 뒤 EMA 기간, 거래량 문턱, 노출, 비용 또는 승인 문턱을 바꾸지 않는다. 외부 검증이 실패하면 후보를 폐기하고 자동 주문은 계속 막는다.

## 경제적 가설

짧은 단일 모멘텀은 횡보장에서 잦게 뒤집혀 비용을 만든다. 반대로 여러 시간축의 추세가 같은 방향으로 모이고, 방향 전환 시점의 4시간 거래량이 직전 7일 수준 이상이면 새로운 정보가 가격에 반영되는 구간일 가능성이 높다는 가설이다.

이 후보는 이전 5초 충격 전략과 다르다.

- 순간적인 거래량 폭발 직후 시장가로 진입하지 않는다.
- 12시간부터 90일까지 다섯 추세를 합성한다.
- 거래량은 신규 방향으로 전환할 수 있는 필수 확인 조건이다.
- 반대 방향이 확인될 때까지 포지션을 유지해 회전율을 낮춘다.
- 명목 노출을 equity보다 작게 유지해 청산이 아닌 전략 반전을 주 종료 규칙으로 사용한다.

## 인과적 판단

1. 연속된 M15 16개로 H4 하나를 만든다.
2. H4 종가·거래량이 모두 확정된 뒤에만 EMA와 거래량 중앙값을 계산한다.
3. 거래량 중앙값은 현재 판단 봉을 제외한 직전 H4 42개만 사용한다.
4. 다섯 EMA 쌍의 다수결이 현재 포지션과 반대여도 현재 H4 거래량이 중앙값 미만이면 전환하지 않는다.
5. 전환이 승인되면 다음 연속 H4 시가에 기존 방향을 종료하고 새 방향을 연다.
6. 누락되거나 16개가 아닌 H4는 신호·수익 계산에서 허용하지 않는다.

EMA 쌍은 H4 봉 개수 기준으로 다음과 같이 동결한다.

| Fast | Slow | 대략적인 시간축 |
|---:|---:|---|
| 3 | 72 | 12시간 / 12일 |
| 6 | 42 | 1일 / 7일 |
| 18 | 180 | 3일 / 30일 |
| 42 | 180 | 7일 / 30일 |
| 42 | 540 | 7일 / 90일 |

최소 540개 H4를 워밍업하고 다섯 표 중 3표 이상인 방향만 사용한다.

## 자본·비용 계약

- 시작 equity: 100, 660, 1,000 USDT를 각각 독립 재생
- 목표 명목 노출: 현재 equity의 65%
- 수량: 0.001 BTC 단위로 내림
- 목표 수량이 최소 수량보다 작더라도 0.001 BTC가 equity의 85% 이하이면 최소 수량 허용
- 반올림 후 명목 노출이 equity의 85%를 넘으면 `NO_TRADE`
- 전략 검증에서는 고정 `MAX_NOTIONAL`을 사용하지 않으며, 100 USDT 고정 상한은 복리 훼손 진단으로만 별도 계산
- 편도 수수료 0.06%, 편도 슬리피지 0.02%
- 기본 비용과 1.5배·2배 비용을 모두 계산
- 실제 funding rate를 정산 시각의 보유 방향과 명목가에 적용
- 주문 직전 equity 기준 명목 노출은 0.85배 이하이며 15배 레버리지를 수익 확대 수단으로 사용하지 않음
- 진입 후 가격 역행으로 equity가 감소하면 `현재 명목가/equity`는 0.85를 넘을 수 있으므로 이를 별도 역행 노출 지표와 MDD로 보고

## 외부 검증

Binance 공식 공개 데이터의 USD-M BTCUSDT H4 kline과 funding rate를 사용한다. 파일별 공개 checksum을 검증하고 원본 파일 목록·SHA-256·행 수·첫/마지막 시각을 manifest에 남긴다. Binance 공식 공개 데이터 저장소는 선물 kline이 `/fapi/v1/klines`에서 만들어지고 월별 파일과 checksum을 제공한다고 명시한다.

외부 거래소에서도 같은 파라미터와 Bybit보다 불리하지 않은 동일 비용 가정을 적용한다. 개발 승인 기준을 모두 통과해야 `HISTORICALLY_VALIDATED_SHADOW_REQUIRED`로만 승격할 수 있다. 거래소가 달라도 BTC 가격 경로의 상관성이 높으므로 외부 거래소 통과만으로 실거래를 승인하지 않는다.

## 실거래 승인까지 남는 게이트

1. Node 연구기와 Kotlin 공통 실행기의 거래·funding·수량 단위 패리티
2. 최소 90일 fresh Bybit shadow
3. 재시작·중복 이벤트·누락 H4·API 장애 시 `NO_TRADE` 검증
4. 거래소 실제 수수료·수량 규칙 조회와 주문 전 노출 재검증
5. 실제 체결 이후 포지션·원장·대시보드 대사
