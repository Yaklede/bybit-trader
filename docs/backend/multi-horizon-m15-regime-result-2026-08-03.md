# 멀티 호라이즌 M15 레짐 필터 실험 결과

## 판정

`multi-horizon-m15-regime-development-v1`은 M5 멀티 호라이즌 모멘텀 전환에
완료된 M15 EMA 레짐 방향을 일치 조건으로 추가한 개발 실험이다. 개발 구간에서
기준선과 거의 같은 결과를 보였고, 사전 고정한 후보를 10개 외부 구간에 그대로
재생한 결과 중앙 CDR이 음수였다. 후보는 `REJECTED`로 종료하며 실거래 프로필로
승격하지 않는다.

## 가설과 인과성 규칙

- M15는 거래소 시간 기준으로 M5 캔들을 집계한다.
- M15 버킷은 해당 버킷의 종가가 M5 신호 캔들 종료 시각 이하일 때만 사용한다.
- M5 모멘텀 전환과 M15 레짐 방향이 같은 경우에만 다음 M5 캔들 시가에서 진입한다.
- 진입·청산 수수료와 양쪽 슬리피지는 기준 실행 계약을 그대로 적용한다.
- 후보 수는 24개로 고정하고, 외부 결과를 확인한 뒤 파라미터를 확장하지 않는다.

## 개발 구간 결과

개발 구간은 `D01`~`D04`이며, 상위 후보는 다음과 같다.

| 후보 | 최악 CDR | 중앙 CDR | 평균 CDR | MDD | 거래 수 |
|---|---:|---:|---:|---:|---:|
| `m15_regime_slope96_scale0.75_votes3_long_only` | `0.00968%` | `0.04502%` | `0.05521%` | `10.52891%` | `301` |

개발 구간 4개 모두 양수였지만, 사전 목표인 일복리 `0.2%`를 한 구간도
충족하지 못했다. 기존 M15 미적용 기준선의 최상위 후보와 비교하면 중앙 CDR은
`0.04667%`에서 `0.04502%`, 평균 CDR은 `0.05537%`에서 `0.05521%`로 사실상
개선되지 않았다.

## 해석

M15 방향 필터는 신호를 줄였지만 방향 오류가 발생한 외부 구간을 제거하지
못했다. 특히 `V02`~`V04`, `V10`에서 손실이 이어져 시장 레짐을 일반화하지
못했다. M15 EMA 방향만으로는 추세 지속과 추세 소진을 구분할 수 없으며,
OHLCV 거래량만으로도 이 한계를 보완하지 못한다.

따라서 다음을 수행하지 않는다.

- 외부 결과를 본 뒤 M15 lookback·threshold·side mode를 추가 탐색
- 이 후보를 `LIVE` 또는 자동 실행 허용 프로필로 등록
- 개발 구간의 양수 결과를 일복리 `0.2%` 달성으로 해석

현재 실험은 “시간 프레임 필터를 추가하면 신규 구간 성능이 개선된다”는 가설을
기각한 기록이다. 다음 전략 실험은 M15 EMA 숫자를 더 조정하는 대신, 진입
신호의 손익 기대값과 비용 후 순손익비를 먼저 계산하고, 필요하면 별도 가설로
전환해야 한다.

## 재현 명령

```bash
node scripts/volume-flow-feature-discovery.mjs \
  --db build/runtime-test/bybit-trader-full-history.sqlite \
  --windows config/volume-flow-development-folds-v3.json \
  --out build/multi-horizon-m15-regime-development-v1 \
  --profile multi-horizon-m15-regime \
  --maxCandidates 24 \
  --targetCdrPct 0.2 \
  --quiet true

  --db build/runtime-test/bybit-trader-full-history.sqlite \

  --profile multi-horizon-m15-regime \
  --candidateId m15_regime_slope96_scale0.75_votes3_long_only \
  --costMultiplier 1 \
  --targetCdrPct 0.2 \
  --quiet true
```
