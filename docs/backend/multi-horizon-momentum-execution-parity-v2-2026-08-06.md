# 멀티 호라이즌 모멘텀 실행 패리티 v2

## 판정

`multi-horizon-momentum-development-v2`의 Node 연구기와 Kotlin 공통 백테스트 엔진은 고정된 실제 BTCUSDT M5 구간에서 거래 단위 패리티를 통과했다. 이 판정은 **실행 결과가 같다는 뜻일 뿐 수익성이 검증됐다는 뜻이 아니다.** 프로필 상태는 `UNVERIFIED`, 자동 실행은 `false`다.

기존 `multi-horizon-momentum-development-v1`은 외부 10개 구간 중 3개만 양수였고 중앙 일복리가 음수였으므로 `REJECTED` 상태를 유지한다.

## v2 실행 계약

- 닫힌 M5 캔들만 신호에 사용한다.
- 신호 다음의 연속된 M5 시가에 방향상 불리한 진입 슬리피지를 적용한다.
- EMA는 첫 종가 시드 방식으로 Node와 Kotlin을 통일한다.
- 구조적 손절선과 ATR 손절 거리를 신호에 분리해 저장한다.
- 최종 초기 손절가는 실제 진입가를 기준으로 계산한다.
- 진입 위험거리가 진입가의 `0.2%` 미만 또는 `3.5%` 초과면 거래하지 않는다.
- 트레일링 스톱은 현재 봉의 기존 스톱 체결 여부를 먼저 확인한 뒤 다음 봉부터 갱신한다.
- 트레일링 기준선에서는 고정 목표가와 부분 익절을 사용하지 않는다.
- UTC 기준 하루 최대 1건만 진입한다.
- 진입과 종료에 각각 `0.02%` 슬리피지, 양쪽 체결에 각각 `0.06%` 수수료를 적용한다.
- 최대 보유 기간 전체가 재생 구간 안에 들어오는 신호만 평가한다.
- 재생 종료 시각은 exclusive다.

## 교차 검증

고정 입력은 `config/multi-horizon-momentum-parity-window-v2.json`이다.

| 항목 | 값 |
|---|---:|
| 워밍업 시작 | `2020-04-30T00:00:00Z` |
| 재생 구간 | `2020-05-30T00:00:00Z` ~ `2020-06-20T00:00:00Z` |
| Node 거래 | 5건 |
| Kotlin 거래 | 5건 |
| 비교 허용오차 | `0.00001` |
| 불일치 | 0건 |
| 판정 | `PASS` |

다음 필드를 모든 거래에서 비교했다.

- 신호, 진입, 종료 시각
- 방향과 종료 사유
- 진입가, 초기 손절가, 종료 트리거가, 실제 종료가
- 단위 위험거리, 거래당 위험 비율
- gross/net R, 손익, 종료 후 잔고

재현 명령:

```bash
node scripts/verify-multi-horizon-parity.mjs
```

생성 증거:

- `build/multi-horizon-momentum-parity-v2/node-trace.json`
- `build/multi-horizon-momentum-parity-v2/kotlin-trace.json`
- `build/multi-horizon-momentum-parity-v2/parity-report.json`

## 패리티 구간 손익 해석

이 구간은 `+5.81539%`, MDD `1.96822%`였지만 5건 중 한 건의 `+9.07718R`이 전체 이익을 만들었다. 양수 거래가 사실상 한 건뿐이므로 단일 거래 이익 기여도 제한 `25%`를 통과할 수 없다. 따라서 이 결과는 수익 증거, 파라미터 선택 근거, 실거래 승격 근거로 사용하지 않는다.
